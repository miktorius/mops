# Демонстрация: закупка оборудования

Дополнительный пример — `examples/equipment-purchase.yaml`. Основная модель приложения
теперь соответствует варианту 1 (см. [проектирование](variant-1-domain.md)).
Для запуска закупки оборудования: `MOPS_MODEL=file:./examples/equipment-purchase.yaml ./gradlew bootRun`,
страница — http://localhost:8080/.

Инициатор подготавливает заявку, руководитель согласует её, специалист по закупкам
подтверждает получение оборудования. Если сумма превышает 100 000 рублей либо
выбран обязательный финансовый контроль, между руководителем и закупками требуется
согласование финансиста. Руководитель и финансист могут вернуть заявку на доработку.
Из подготовки заявку можно отменить. Получение и отмена — конечные состояния.

## Пользователи

| Пользователь | Роль |
|---|---|
| `demo` | Все роли — удобно пройти весь маршрут без переключений |
| `anna` | Инициатор: запуск, отправка, отмена |
| `mikhail` | Руководитель: согласование, возврат |
| `olga` | Финансист: финансовое согласование, возврат |
| `elena` | Специалист по закупкам: подтверждение получения |

## Готовые заявки

| Объект | Что показывает |
|---|---|
| `request-office` — монитор и принтер, 45 000 ₽ | Короткий путь: подготовка → руководитель → закупка → получено |
| `request-laptop` — рабочее место, 180 000 ₽ | Дополнительное согласование бюджета |
| `request-mandatory` — принтер, 15 000 ₽ | Финансовая проверка обязательна даже при малой сумме; вторая группа ДНФ |
| `request-empty` | Отказ при отправке: в составе нет оборудования |
| `request-over-limit` | Отказ при отправке: сумма 250 000 ₽ превышает ограничение класса заявки |

На странице выберите пользователя и заявку, нажмите «Запустить процесс».
После запуска появятся действия текущего состояния и их условия. Зелёным отмечено
текущее состояние, зелёная стрелка показывает последний выполненный переход.
Возвраты проведены над диаграммой. Наведение на стрелку показывает её условие.
Для процессов, изменённых через API, используйте «Обновить состояния».

Для проверки роли отправьте обычную заявку от Анны, затем попробуйте выполнить
«Согласовать» от неё же. Команда будет отклонена, состояние на диаграмме сохранится.
Переключитесь на Михаила и повторите согласование — заявка перейдёт в закупку.

Класс заявки наследует у документа название, подразделение и сумму. Диапазон суммы
полностью переопределён: для заявки 1 000–200 000 ₽ вместо 0–1 000 000 ₽.
Параметр `equipment` ссылается на объекты оборудования; допускается 1–5 элементов.
Агрегатор `all` проверяет цену каждого элемента по границам его фактического класса,
включая подкласс ноутбука с собственным диапазоном 30 000–150 000 ₽.
Сумма заявки задана в исходных данных, автоматического суммирования цен нет.

Все команды сохраняются в `logs/processes.jsonl`. Перезапуск приложения очищает
состояния процессов, поэтому демонстрацию можно повторить с начала.
